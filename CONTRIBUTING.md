# Contributing to sasonr

Thank you for your interest in sasonr. The project aims to run SAS programs
on an R engine with results identical to SAS 9.4, and to translate SAS into
R deterministically. Contributions of code, test cases and documentation are
welcome.

## Ground rules

1. **SAS output is the only source of truth.** A feature is accepted only
   when its test cases reproduce output generated by SAS 9.4. Expected values
   written by hand, taken from documentation examples or produced by another
   interpreter are not accepted.
2. **Fail loud.** Anything not verified against SAS must stop with a
   `sasonr_unsupported` condition naming the feature and the SAS line. Silent
   approximation is a bug.
3. **Deterministic.** No language model or network service is used at run
   time.
4. **No proprietary or personal data.** Test programs use invented data
   (`datalines`). Never add real study data, SAS-owned data sets or text
   copied from books or manuals.

## Development setup

```r
# install dependencies and load the package
pak::pak("kaipingyang/sasonr")
devtools::load_all()
devtools::test()
```

## Code conventions

* tidyverse style, `|>` pipe, `snake_case`.
* Naming:
  * `sas_run()`, `sas_translate()`, `sas_lex()`, `sas_parse()`: user API;
  * `sas_f_<name>()`: implementation of the SAS function `<NAME>`;
  * `sas_fmt_*()`: formats and informats;
  * `sas_proc_<name>()`: R interface of a procedure;
  * runtime helpers called by generated code are internal.
* Every change needs tests; behaviour changes need a conformance case.

## Adding a conformance case

See the article *Adding a conformance case* in the Developers menu of the
documentation site. In short: write `program.sas` with invented data, run it
with SAS 9.4 to produce the expected output, sanitise it with
`tools/sanitize.py`, and add the case. If you do not have SAS, open an issue
with the program and the label `needs-gold`; a maintainer will generate the
expected output.

## Pull requests

* One topic per pull request; describe which SAS behaviour is affected and
  link the conformance cases.
* `devtools::test()` and `R CMD check` must pass.
