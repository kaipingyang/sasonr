# The log of a result or a session

The log as plain text, as text coloured for the terminal, or as HTML.

## Usage

``` r
sas_log(
  x,
  format = c("plain", "ansi", "html"),
  echo = log_echo_default,
  ...,
  compact = FALSE,
  session
)
```

## Arguments

  - x:
    
    A result of `sas_run()` or a session from `sas_session()`.

  - format:
    
    `"plain"`, `"ansi"` or `"html"`.

  - echo:
    
    Show the program lines (`TRUE`, the default) or only the messages
    and PUT output (`FALSE`).

  - ...:
    
    Not used; the arguments after it are given by name.

  - compact:
    
    The compact layout of the echo (`TRUE`) or the default layout with
    the line numbers in 11 columns (`FALSE`, the default).

  - session:
    
    The former name of `x` (a session), still accepted; with `session`,
    `x` is left out (or is the format, given by position).

## Value

`"plain"` and `"ansi"`: a character vector of class `sasonr_log`, one
element per line; it prints as the log text, one line per element.
`as.character()` gives the plain character vector; `[` keeps the class.
`"html"`: a character string.

## Details

  - `"plain"`: the SAS-style log text, one element per line: the lines
    of `x$log` (for a session: the log of all submissions).

  - `"ansi"`: the same lines coloured with cli (ERROR red, WARNING
    green, NOTE blue, PUT output unstyled), under a summary line that
    counts the ERROR and WARNING lines of the messages (PUT output that
    starts with `ERROR:` is not counted). `print()` of a result uses
    this view in a terminal with colours; `options(sasonr.log_style =
    "plain")` turns it off.

  - `"html"`: one string, a `<div class="sas-log">` with a `<details>`
    block per step and the lines in `<span>` elements of the classes
    `sas-note`, `sas-warning`, `sas-error`, `sas-put` and `sas-src`
    (source lines). The style sheet is `system.file("css", "sasonr.css",
    package = "sasonr")`; the HTML has no inline styles.

Every view shows the program lines with their line numbers (`echo =
FALSE`: the messages and PUT output only): each line with its number
left-justified in 11 columns, a line longer than `LINESIZE` continued on
lines that start with `!`; a compile-time ERROR right after its line,
with an underscore marker and the error number under the line when the
column is known; a blank line after a numbered ERROR message
(`ERROR 22-322: ...`, except in PROC MEANS, SUMMARY, UNIVARIATE,
TRANSPOSE, COMPARE, SORT, FREQ, RANK, APPEND and CONTENTS when more of
the step's lines follow); a blank line between a step's lines and what
the step writes when it runs (when the step ends on the line of its
numbered ERRORs, this blank line comes before them and each of them is
followed by a blank line). The data lines after `DATALINES` / `CARDS`
are not echoed. The program's `OPTIONS SOURCE` and `OPTIONS NOSOURCE`
turn the echo on and off.

Limits of the echo: it shows the lines of the program as written,
numbered from 1 in each submission (a session does not continue the
numbering); code generated by macros (MPRINT lines) and `%INCLUDE` lines
are not shown; the NOTEs written while a step is compiled follow the
step's lines; the statements of a PROC SQL step that share a line are
not split onto `!` lines; a line on which `RUN;` is followed by more
text is echoed whole (in SAS the rest follows the step's messages);
lines with multibyte characters wrap by characters; the timing NOTEs of
SAS are not written. When the echo cannot be shown exactly, the echo of
that submission is left out and the log starts with a NOTE that says
why; the run itself goes on: a numbered ERROR on a line with a macro
reference (a macro variable, call, statement or comment), a compile-time
ERROR on a line that `OPTIONS NOSOURCE` hides, `OPTIONS SOURCE` /
`NOSOURCE` with more text on its line, a numbered WARNING. For now a
NOTE place (`(Line):(Column)`, `at line N column M`) on a line with a
macro reference fails loud.

`compact = TRUE` is a narrower layout of the echo for display: the line
number takes as many columns as the largest line number of the view
needs, plus one blank; a continuation line starts with `!` in those
columns. The lines break where they do in the default layout, and the
underscore markers and error numbers under a line move with its text.
The messages are unchanged (the places in a NOTE are program lines and
columns).

## See also

The events behind every view are the `log_events` field of a result (a
tibble: `seq`, `submission`, `step`, `phase`, `kind`, `id`, `args`,
`at`, `places`, `text`, `source_line`).

## Examples

``` r
res <- sas_run("data a;\n  x = 1;\n  put x=;\nrun;")
sas_log(res)
#> 1          data a;
#> 2            x = 1;
#> 3            put x=;
#> 4          run;
#> 
#> x=1
#> NOTE: The data set WORK.A has 1 observations and 1 variables.
sas_log(res, echo = FALSE)
#> x=1
#> NOTE: The data set WORK.A has 1 observations and 1 variables.
sas_log(res, compact = TRUE)
#> 1 data a;
#> 2   x = 1;
#> 3   put x=;
#> 4 run;
#> 
#> x=1
#> NOTE: The data set WORK.A has 1 observations and 1 variables.
cat(sas_log(res, "html"))
#> <div class="sas-log">
#> <p class="sas-log-summary">No ERRORs or WARNINGs</p>
#> <details class="sas-step" open><summary>DATA step (line 1)</summary>
#> <pre class="sas-log-text"><span class="sas-src">1          data a;</span>
#> <span class="sas-src">2            x = 1;</span>
#> <span class="sas-src">3            put x=;</span>
#> <span class="sas-src">4          run;</span>
#> <span class="sas-src"></span>
#> <span class="sas-put">x=1</span>
#> <span class="sas-note">NOTE: The data set WORK.A has 1 observations and 1 variables.</span></pre>
#> </details>
#> </div>
res$log_events[, c("step", "kind", "id")]
#> # A tibble: 3 × 3
#>    step kind  id        
#>   <int> <chr> <chr>     
#> 1     1 echo  raw       
#> 2     1 put   raw       
#> 3     1 note  ds.created
```
